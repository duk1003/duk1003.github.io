이 글에서는 알고리즘에서 가장 기본이 되는 Computational Efficiency에 대해 알아보겠습니다. 알고리즘을 작성하는 과정에서 가장 신경써야 하는 부분은 알고리즘이 알맞게 작동하는지 여부입니다. 그 다음으로 신경써야 하는 부분이 알고리즘이 원하는 시간과 공간 안에 작동하는지 여부입니다. 몇 가지 예제를 통해 같은 문제를 해결할 때 사용되는 알고리즘에 따라 시간복잡도가 얼마나 변하는지를 살펴보겠습니다.

```
Fib1(n)
if n = 0 then return 0
else if n = 1 then return 1
return Fib1(n-1) + Fib1(n-2)
```
위 알고리즘은 피보나치 수열의 n번째 값을 구하는 알고리즘입니다. 피보나치 수열의 정의에 맞게끔 Fib1(n) = Fib1(n-1) + Fib1(n-2) 식을 통해 피보나치 수열의 값을 구하게 됩니다. 이 알고리즘은 알맞게 작동하지만, 그 구조를 생각했을 때 시간복잡도를 구해보면, n <= 1에서 T(n) <= 2입니다. T(n) = T(n-1) + T(n-2) + O(1)이므로, T(n) >= F_n이 됩니다. 즉, 입력 값이 n인 알고리즘의 소요 시간은 n번째 피보나치 수열값보다 크다는 것입니다. 따라서, T(n) = O(1.6^n)입니다. 이는 n이 작은 경우에는 별 문제없이 작동하지만, n이 클수록 너무 긴 소요시간을 가지게 됩니다. 예를 들면, Fib(100)은 1.6^100으로 대략 12일 가량이 소요됩니다. 이렇게 긴 소요 시간을 줄이기 위해서 아래와 같은 형태로 개선이 가능합니다.

```
Fib2(n)
if n = 0 then return 0
create an array f[0, ..., n]
f[0] = 0, f[1] = 1
for i = 2, ..., n do f[i] = f[i-1] + f[i - 2]
return f[n]
```
이 알고리즘의 경우에는 한 번 계산한 i번째 피보나치 수열 값을 배열에 저장해두기 때문에 반복해서 계산할 필요없이, n번째까지의 피보나치 수열값을 한 번씩만 구하면 충분합니다. 따라서, 이 알고리즘의 시간 복잡도는 O(n)이 됩니다. 이 알고리즘보다도 행렬 곱을 사용하면 피보나치 수열의 값을 구하는 과정을 O(logn)으로 줄이는 방법도 존재합니다. 여기서 시간 복잡도의 크기를 비교하자면, 아래와 같습니다.
```
logn < n < nlogn < n^2 < n^3 < 1.5^n < 2^n < n~
```

이번에는 새로운 예제인 Convex Hulls에 대해 알아보겠습니다. 이 문제는 평면 위에 여러 좌표들이 주어졌을 때, 해당 좌표들의 겉을 감싸는 가장 작은 다각형 형태의 경계를 구하는 문제입니다. 입력으로는 좌표 집합 P = {p1, p2, ..., pn}과 각 pi = (xi, yi)로 구성되고, 출력으로는 convex hull을 구성하는 좌표들을 출력하면 됩니다. 이 문제를 해결하기 위한 중요한 아이디어는 세 점 p, q, r이 주어졌을 때, 이 세 점이 시계방향인지, 시계 반대방향으로 배치되어 있는지 판별하는 것입니다. 이는 아래 공식을 통해 판단할 수 있습니다.
```
r lies to the left of pq iff (r_y - p_y)(q_x - p_x) > (q_y - p_y)(r_x - p_x)
```
하지만, 이 공식을 사용하더라도 모든 점에 대해 전체 탐색을 하게되면, 시간 복잡도는 O(n^3)이 됩니다. 따라서, 여기서는 Graham's scan이라고 하는 방법으로 문제를 해결할 수 있습니다. 우선, 모든 점을 x축에 대해 정렬합니다. 이후, 정렬 순서대로 점 p, q, r을 잡고 다음 과정을 반복합니다. r이 pq와 시계방향으로 배치된다면, 정렬된 배열에서 한 단계 앞으로 이동합니다. 만일 r이 시계 반대방향으로 배치된다면, q를 배열에서 지우고, 배열에서 한 단계 뒤로 이동합니다. 이 과정을 반복하면 convex hull의 윗 부분을 완성할 수 있고, 기존 배열에서 같은 과정을 방향만 바꾸면 convex hull의 아래 부분을 완성하여 convex hull을 구할 수 있습니다. 이 알고리즘의 시간복잡도는 정렬을 위한 O(nlogn)과 graham's scan을 위한 O(n)으로 구성되어, 최종적으로 O(nlogn)의 시간복잡도를 가집니다.

아래의 여러 정의들은 시간 복잡도를 나타내는 여러 표기법과 그 특정들을 나열하고 있습니다.
```
f(n) is O(g(n)) iff there exist constants c > 0 and n_0 >= 0 s.t. for all n >= n_0 we have f(n) <= cg(n)
f(n) is Ω(g(n)) iff there exist constants c > 0 and n_0 >= 0 s.t. for all n >= n_0 we have f(n) >= cg(n)
f(n) is Θ(g(n)) iff f(n) is Ω(g(n)) and O(g(n))
f = o(g) iff for all c > 0, there exists an n_0 > 0 s.t. f(n) <= cg(n) for all n >= n_0, g = w(g)
Transitivity : if f = O(g)/Ω(g)/Θ(g) and g = O(h)/Ω(h)/Θ(h) then f = O(h)/Ω(h)/Θ(h)
Additivity : if f = O(h)/Ω(h)/Θ(h) and g = O(h)/Ω(h)/Θ(h) then f+g = O(h)/Ω(h)/Θ(h)
Limits :  lim_{n→∞}f(n)/g(n) reveals some asymptotic relationship between f and g
Polynomials : a0 + a1n + ... + adn^d is Θ(n^d) if ad > 0. => Running time is O(n^d) for some constant d independent of the input size n.
Loarithms : O(log_an) = O(log_bn) for any constants a,b > 1
For every fixed constant x > 0, logn = O(n^x) => every polynomial grows much faster than log
Exponential : for every r > 1 and every d > 0, n^d = O(r^n) => every exponential grows faster than every polynomial
```
